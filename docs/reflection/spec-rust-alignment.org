#+TITLE: Reflection: SPEC and Rust Library Alignment
#+OPTIONS: toc:nil

* LeanPoo assessment for this iteration

The existing SPEC protection profile uses LeanPoo typed slots and inheritance
to compose an intent from the storage effect and key configuration. This
iteration did not add another independently owned profile. The fixture pin
check compares immutable Git-tree bytes, the Google Table request repeats one
already selected recipe over ordered rows, and protected recovery observes
physical outbox failures. None has inherited methods, competing owner order,
or a proof dependency graph that LeanPoo could compose or cache usefully.
Current claims and ledger rows must still be refreshed by the Host; a cached
LeanPoo Allow would not authorize a later read or provider release.

* Executable evidence and limit

[[file:../../tools/check-spec-fixtures.py][The pin gate]] compares four Rust
fixtures with the exact Cargo-pinned SPEC Git tree. SPEC's
[[https://github.com/tao3k/cedar-poo-spec/pull/5][Table Batch Wire V1]]
adds checked ordered response cases replayed by its Rust bridge. MRR Data
retains MRR row identities while forming one Table request and rejects an
incomplete or mismatched response without returning checked outputs. The
protected recovery test denies a missing outbox, corrupt manifest, or child-map
drift in a recovered record before the encrypted outer root can be published.
These checks do not authenticate
the Host record, provider response or Cedar decision, perform a durable ledger
transaction, or reverse provider side effects.

* Reconsideration trigger

If separate owners begin contributing inherited table recipes or protection
profiles, compose those declared rules with LeanPoo and test owner order and
deny preservation. Keep byte provenance, physical I/O and current authority
checks at their existing boundaries.

* Reflection: equal-context row association

The existing LeanPoo protection profile still composes independently owned
storage and key choices. This iteration adds a generated marker to one Google
Table request because two rows can share the same context while carrying
different MRR identities. Marker equality and serialized wire size are direct
value checks; they do not use inherited methods or proof dependencies. The
SPEC fixture and Rust bridge reject reordered or duplicate markers, and MRR
retains its selected Arrow row identity only after the whole response passes.
The Host must still authenticate transport and authorize each selected row.
