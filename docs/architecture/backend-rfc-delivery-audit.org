This audit reads PR #12 at =d36337b703c0a1f5bd0fa1eaaa62d11178e6507f=.
Its latest addition pins the DuckGQL interface research gate; runtime changes
remain those at =16c111c8=. At audit time the exact-head CI had Arrow IPC fuzz

* Architectural decisions retained

- MRR owns canonical identities, catalog, graph-query semantics and result admission.
- GraphAr is the provider-independent physical graph foundation for Production
  graph workloads, including topology, adjacency/offsets and property groups.
- Arrow provides typed interchange; the shared Backend owns one Host runtime
  lifecycle, admission, leases, publication/recovery and drain.
- Native Turso/DuckDB are optional transaction/execution providers. Engine
  tables, indexes and extension CSR state are derived images of verified sources.
- DuckGQL is a separately gated extension, not native DuckDB graph capability.
  Its availability and benchmarks do not gate GraphAr persistence/selective access.
- Production owns the common contract; no Example, profile-specific runtime or
  reverse dependency changes that ownership.

See [[file:0001-mrr-data-plane.org][the canonical data plane]], [[file:shared-backend.org][shared Backend]],
[[file:../rfcs/0002-graphar-arrow-backend.org][RFC 0002]] and [[file:../rfcs/0003-gql-duckdb-turso-backends.org][RFC 0003]].

* Findings that change the execution plan

** Delivered slice: queued explicit stop

The queued stop slice is now implemented. =ResourceControl= has a sticky
notification and the dispatcher races both resource/shared permit waits against
explicit cancellation and the Host-clock deadline. It drops owned request input
and its reservation before returning a typed stop. The held-worker fixture
covers both lanes without releasing the held worker, including a future deadline
and a live explicit-cancel waiter. Running native calls still retain admission
through cleanup; queue timers do not assert native interruption.

** P1: ownership budgets are contractual, not a physical memory ceiling

=ResourceHandle::get= borrows a value but cannot prohibit callers from cloning
=PhysicalQueryOutput=. MRR projection currently consumes an owned output, and
source captures use shared decoded facts. Keep the lease through conversion and
admission, and explicitly reserve conversion/candidate scratch or transfer
accounting to another owner before exporting clones. Do not describe logical
reserved bytes as native RSS or as enforcement over arbitrary Rust clones.

=ResourceHandle::try_transform= now consumes unique ownership and carries its
existing lease into the converted representation. Shared handles are refused
without running conversion; conversion failure releases admission. The native
Turso fixture consumes physical output into an MRR candidate, admits it and
keeps the candidate lease through drain, without cloning the physical result.
Host conversion scratch is still explicitly budgeted. This provides a library
handoff receipt, not a deployed Host invocation.

Qualify that handoff through a simulated Host caller before broadening results;
include a retained clone and conversion overlap, not only handle-drop tests.
A borrowed/consuming lease-aware conversion API should be selected from actual
MRR caller requirements rather than introducing a second result model.

** P1: GraphAr strategic role requires a selective execution source

Current =CapturedGraphArSnapshot= retains =Arc<[Fact]>= after complete decoding.
This proves immutable bounded capture, not source-pinned adjacency cursors or
selective property scans. Rebuilding an SQL table from all captured facts on
an invocation does not demonstrate scalable graph access.

Deliver a checked outgoing-neighborhood scan for the existing binary-Entity
projection before inventing another query planner. Retain verified chunks and
source binding under the shared Backend lease. Specify source versus destination
layout support, offset bounds, endpoint/FactId mapping and property-row alignment.

Selective reading must preserve integrity: the current inventory/root design
may still require reading every declared file to verify the closure. Record
integrity-verification bytes separately from execution-read bytes. Claim reduced
end-to-end I/O only with a qualified authenticated chunk/cache design, never by
skipping closure validation. Source mutation, stale bindings, malformed offsets
and property/topology misalignment must yield no admitted candidate.

** P2: distinguish current emitter from proposed generalized SQL plan

RFC 0003 describes a future =PreparedSql= and multi-shape typed plan. Current
code exposes =TursoSingleHopSql= for a deliberately narrow fixed mapping. It
has no delivered general SQL plan, property filter, arbitrary parameter mapping
or multiple-engine renderer. Mark the generalized section as proposed and tie
each expansion to an MRR semantic slice and independent expected rows.

** Independent research gate: DuckGQL

Upstream typed-plan entrypoint, extension ABI/binary compatibility and canonical
identity/result ordering require separate prototypes. No qualified bridge is
implemented. Keep that work independent of GraphAr and Turso delivery. Do not
replay source GQL into a second semantic binder to manufacture completion.

P1-D security/durability can proceed independently of selective-read development;
it cannot be omitted from production qualification because a query fixture passes.
Use focused tests for each seam. Existing native CI already runs the whole Turso
crate, including cleanup unit tests. No repeated full native rebuild or additional
provider should be introduced without a concrete unresolved acceptance risk.

* Performance experiment contract

The first experiment compares full capture and selective execution reads of
one published binary-Entity graph. Use independent expected rows, varied degree
skew, isolated cold/warm verification/cache states and identical MRR result
ordering/admission. Measure setup/verification, data bytes, decode/copy, query,
first/total result, retained reservations, actual native RSS and spill separately.
Do not infer peak memory from row limits or infer throughput from build/test time.
DuckGQL comparison starts only when its bridge is qualified; GraphAr delivery
continues without it. Performance results decide optional execution optimizations,
not the physical graph foundation's architectural position.

* Definition of closure

A slice is closed only when its implementation, refusal/lifecycle fixtures,
exact-head platform checks and RFC status agree. Current P0–P2 closure concerns
the framework: simulated Host authorization and original-query callers, native
local providers, and local process/fault injection are sufficient evidence.
Deployment credentials, live Lambda/Marlin processes and deployed object stores
are not prerequisites. Future product deployment requires its own integration
acceptance. General graph-query conformance and hard native deadlines remain
unclaimed until individually qualified.

* Current execution checkpoint

Implemented this slice: queued explicit cancellation/deadline and consumption
of physical output into a leased MRR candidate. Focused resource/native tests,
workspace policy and strict native adapter lint are the local gates. Remote
exact-head acceptance must be recorded separately after publication.

GraphAr selective native access still requires extending the pinned safe reader:
current writer uses =UnorderedBySource=, and the reader's safe edge API provides
whole-source batch export rather than a vertex/chunk range cursor. A full scan
with a Rust-side filter is not selective I/O. Ordered adjacency publication and
range/offset-aware safe reader qualification must precede the claimed P1-C gate.

Host inputs are simulated in this stage. Use the existing Backend authority
CAS for policy/key enrollment, rotation and retirement; serialize final protected
disclosure with those changes in the simulated Host. Historical recovery remains
a receipt lookup, never fresh disclosure permission. Original Lambda/Marlin
query bytes and expected rows can run through local simulated callers.
Publication-phase process-crash injection, selective graph access, original
property-path expansion and the matched performance matrix remain outstanding.

** Simulated Host authority contract

=backend_consumer::authorities::simulated_host_disclosure_rotation_retirement_and_replay_are_separate=
uses the existing native Backend with a local simulated Host. It enrolls separate
policy and key commitments, binds both to a fresh content effect, refuses omitted
or stale guards, rotates the key, and orders final disclosure before concurrent
policy retirement. Canceled pending disclosure emits nothing. Historical replay
and exact receipt recovery remain available after retirement, while disclosure
is refused both before and after native reopen.

All mutations and final disclosure pass through one simulated Host boundary.
This qualifies that single-Host contract; it does not claim that a local mutex
coordinates independent processes or that Backend CAS alone authorizes payload
release. A future distributed Host supplies its own equivalent final-disclosure
coordination. No live credential or deployed service is needed for this fixture.

Local simulated-Host acceptance: the same consumer passes with native Turso
=0.8.1= and DuckDB; strict Backend consumer clippy (=--profile test=,
=-D warnings=), formatting and diff checks pass. Remote acceptance of the new
commit remains a separate exact-head CI gate.
