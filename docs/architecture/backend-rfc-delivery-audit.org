** Milestones, dependency order and exit criteria

*** Strategic review: GraphAr and the complete next delivery

Review baseline: clean local =c6e26f11=, with local original-source acceptance
=DataFusion 2 / GraphAr 2= and Python =40=. Published =56b7057a= remains a
separate frozen CI baseline. At this review its Linux original-source and
maintained GraphAr jobs, MSRV, Arrow fuzz and both S3 jobs pass; Python fails,
and macOS original-source/GraphAr, general Rust and both DuckGQL jobs remain
pending. Local fixes and older platform passes do not close current-head gates.

GraphAr is the common durable physical representation for Production graph
workloads. Its strategic value follows from a graph-aware adjacency/offset layout,
independently projected property groups, immutable chunk reuse and interoperable
storage across execution engines. [[https://graphar.apache.org/docs/overview/concepts/][The official format concepts]] describe the
source/destination adjacency layouts and chunk/property separation;
[[https://arxiv.org/html/2312.09577v4][the GraphAr paper]] motivates neighbor access and label filtering as distinct
physical operations. These support the architecture choice, not a performance
claim about the current MRR implementation or a guarantee that every published
feature exists in the pinned Rust/C++ SDK.

| Architectural responsibility | Owner | Strategic delivery boundary |
|------------------------------+-------+-----------------------------|
| Original source, catalog/generation, semantic identities, final candidate admission | MRR | Engine output always returns through the original admitted query |
| Graph metadata, vertex/edge properties, adjacency/offset layout | GraphAr adapter | One immutable representation contract; typed descriptors vary by profile |
| Reservations, queues, cancellation, retained buffers, drain and close | Shared Production Backend | One runtime/admission model for all profiles and physical capabilities |
| Immutable content, transfer/cache, root binding and publication closure | MRR Data content/snapshot layer | GraphAr metadata and native chunks bind to exact CIDs; the file format is not the authorization authority |
| Atomic heads, authority versions and recovery history | Optional metadata transaction provider | Storage-independent transaction protocol; SQL stays inside optional implementations |
| Columnar interchange | Arrow | Explicit schema, buffer lifetime/release and actual copy accounting |
| Physical scan/join/filter and narrow extension dispatch | DataFusion/DuckDB/DuckGQL/Turso query adapters | Supported operators differ; execution images can be rebuilt from the admitted snapshot |

GraphAr format selection does not supply MVCC, atomic publication, authority
retirement or crash recovery. Those existing contracts must remain visible.
The persistence contract serves every graph-using Production profile without
forcing native GraphAr or a database onto consumers that only need semantic
types or opaque metadata. No provider owns a second independent Backend.

The main performance risk is paying full-snapshot verification and full fact
materialization before every selective query. The current selective implementation
has positioned Parquet reads, offsets and row selection; the canonical combined
caller still captures its full physical closure. The next optimization must join
those paths and measure authentication, cold acquisition, materialization and
query independently. Global required coverage cannot be dropped to make a slice
benchmark look faster. Reuse verified immutable source ownership first; selective
cold acquisition requires an explicit integrity/coverage contract before release.

GraphAr durable chunk size, Parquet row group size, Arrow batch byte limit and
native engine vector capacity are separate parameters. Chunk/property layouts
need measured workload selection, not a universal row count. Current native VTab
copy/registry boundaries also prevent an end-to-end zero-copy claim. [[https://arrow.apache.org/docs/format/CDataInterface.html][Arrow's C Data
ownership contract]] and [[https://duckdb.org/docs/current/clients/rust/result_handling][DuckDB's Rust result-handling contract]] require precise
release and streaming behavior; iterating batches does not itself bound engine
RSS or remove a blocking operator's internal materialization.

The cross-profile acceptance must reuse real supported graph schemas with
distinct profile bindings; differing metadata keys alone prove metadata isolation,
not an entire second Production graph case. Incoming traversal, broad GQL,
arbitrary property/n-ary profiles, specialized label encodings and further engines
are deferred until a concrete Production query establishes need and its acceptance
contract. Paper algorithms are research candidates, not implicitly implemented
features. Prioritize graph correctness/lifetime and then measured scan/reuse gains
ahead of expanding provider count.

Keep one ledger and publish complete milestone batches. Native owner progress
streaming, Python toolchain setup, exact-source platform acceptance and the Linux
DuckGQL cold-build deadline are the present engineering gates. Simulated Host
authorization remains sufficient; live deployment credentials, a universal SQL
compiler, an independent graph runtime per provider or relaxed timeouts are not
added to this plan.

** Scope and progress discipline

Critical path: =M0 -> M1 -> M2 -> M3=. P0 means baseline/platform acceptance;
P1 means complete correctness and lifecycle; P2 means measured reuse/optimization.
Do not restart the plan around each helper function.

Keep arbitrary graph-language conformance, additional property/n-ary profiles,
incoming layouts, hard native preemption, generalized SQL plans, releasable VTab
registration and deployed cloud acceptance in an explicitly scoped backlog.

Turso stays =0.8.1=, Cargo parallelism stays default, and Python remains glue-only.

Each milestone update reports: integrated head, delivered caller capability,
positive/refusal/lifecycle receipts, current-head CI and the next actual blocker.
Publish milestone-sized batches when reviewable, preserving urgent safety fixes
as focused exceptions. Full native CI remains mandatory at milestone exits;
focused local checks qualify intermediate changes. Freeze the head while resolving
its platform failures instead of repeatedly replacing pending evidence.

- MRR owns canonical identities, catalog, graph-query semantics and result admission.
- GraphAr is the provider-independent physical graph foundation for Production
  graph workloads, including topology, adjacency/offsets and property groups.
- Arrow provides typed interchange; the shared Backend owns one Host runtime
  lifecycle, admission, leases, publication/recovery and drain.
- Native Turso/DuckDB are optional transaction/execution providers. Engine
  tables, indexes and extension CSR state are derived images of verified sources.
- DuckGQL is a separately gated extension, not native DuckDB graph capability.
  Its availability and benchmarks do not gate GraphAr persistence/selective access.
- Production owns the common contract; no Example, profile-specific runtime or
  reverse dependency changes that ownership.

[[file:../rfcs/0002-graphar-arrow-backend.org][RFC 0002]] and [[file:../rfcs/0003-gql-duckdb-turso-backends.org][RFC 0003]].

* Initial findings and subsequent implementation receipts

** Delivered slice: queued explicit stop

The queued stop slice is now implemented. =ResourceControl= has a sticky
notification and the dispatcher races both resource/shared permit waits against
explicit cancellation and the Host-clock deadline. It drops owned request input
and its reservation before returning a typed stop. The held-worker fixture
covers both lanes without releasing the held worker, including a future deadline
and a live explicit-cancel waiter. Running native calls still retain admission
through cleanup; queue timers do not assert native interruption.

** P1: ownership budgets are contractual, not a physical memory ceiling

=ResourceHandle::get= borrows a value but cannot prohibit callers from cloning
=PhysicalQueryOutput=. MRR projection currently consumes an owned output, and
source captures use shared decoded facts. Keep the lease through conversion and
admission, and explicitly reserve conversion/candidate scratch or transfer
accounting to another owner before exporting clones. Do not describe logical
reserved bytes as native RSS or as enforcement over arbitrary Rust clones.

=ResourceHandle::try_transform= now consumes unique ownership and carries its
existing lease into the converted representation. Shared handles are refused
without running conversion; conversion failure releases admission. The native
Turso fixture consumes physical output into an MRR candidate, admits it and
keeps the candidate lease through drain, without cloning the physical result.
Host conversion scratch is still explicitly budgeted. This provides a library
handoff receipt, not a deployed Host invocation.

Qualify that handoff through a simulated Host caller before broadening results;
include a retained clone and conversion overlap, not only handle-drop tests.
A borrowed/consuming lease-aware conversion API should be selected from actual
MRR caller requirements rather than introducing a second result model.

** P1: GraphAr strategic role requires a selective execution source

Current =CapturedGraphArSnapshot= retains =Arc<[Fact]>= after complete decoding.
This proves immutable bounded capture, not source-pinned adjacency cursors or
selective property scans. Rebuilding an SQL table from all captured facts on
an invocation does not demonstrate scalable graph access.

Deliver a checked outgoing-neighborhood scan for the existing binary-Entity
projection before inventing another query planner. Retain verified chunks and
source binding under the shared Backend lease. Specify source versus destination
layout support, offset bounds, endpoint/FactId mapping and property-row alignment.

Selective reading must preserve integrity: the current inventory/root design
may still require reading every declared file to verify the closure. Record
integrity-verification bytes separately from execution-read bytes. Claim reduced
end-to-end I/O only with a qualified authenticated chunk/cache design, never by
skipping closure validation. Source mutation, stale bindings, malformed offsets
and property/topology misalignment must yield no admitted candidate.

** P2: distinguish current emitter from proposed generalized SQL plan

RFC 0003 describes a future =PreparedSql= and multi-shape typed plan. Current
code exposes =TursoSingleHopSql= for a deliberately narrow fixed mapping. It
has no delivered general SQL plan, property filter, arbitrary parameter mapping
or multiple-engine renderer. Mark the generalized section as proposed and tie
each expansion to an MRR semantic slice and independent expected rows.

** Publication process-exit matrix

=backend_graph_publication::publication_process_exit_preserves_original_operation_and_complete_head=
runs a native provider in an independent child process and exits without Backend
shutdown or Rust destructors at eight boundaries: first child write before ACK,
inventory write before ACK, snapshot write before ACK, before binding-root upload,
root write before ACK, complete publication ACK before CAS, before provider CAS,
and after native commit before returning its receipt. Each child has a 30-second
watchdog; its exit code must identify the configured fault rather than a passing
or accidentally failing harness.

The parent seeds an existing head and policy guard, reopens native state, and
recovers only the original operation. Before commit it requires confirmed
absence and an exact-prior-head retry; after commit it requires the exact next
revision and validator-free replay. Cold restore reads file-backed simulated
remote blocks and requires root, block count and byte-count parity. Incomplete
child/metadata closure is refused; a root written before a lost ACK remains
restorable but does not advance the selected head.

This qualifies local process exit at publication/provider boundaries with opaque
transport fixture bytes. Native GraphAr/Arrow format qualification remains in
its separate facade consumer. It does not interrupt the native COMMIT call or
attest power loss, filesystem/object-store durability across machine failure, or
independent deployed services. Existing =backend_consumer= uncommitted-transaction
process-exit fixtures cover a separate native metadata rollback boundary.

** Ordered outgoing snapshot source and matched physical work

=GraphArSelectiveSnapshot= authenticates the query/binding/projection, copies
and CID-verifies every declared inventory file, admits the native vertex index,
and reads ordered offsets once. It checks first offset zero, nonnegative monotone
offsets, real vertex tail and padded tail equal the declared edge count. It then
opens read-only topology/property descriptors and deletes the private directory
before returning. Original-directory mutation/deletion cannot change retained
bytes. The final handle closes descriptors without deferred recursive deletion.
Linux/macOS are the qualified platforms; unlinking open files is not claimed
as a portable Windows lifetime contract.

Outgoing access uses positional reads, cached offsets, row selection and boundary
probes. It validates selected source IDs, endpoint bounds, exact topology/property
row counts and fields, canonical identities, FactId uniqueness within the slice,
projection and generation. It rejects shifted/truncated offset intervals rather
than accepting incomplete neighborhoods. A selected slice is physical MRR facts,
not a whole relation, a general query result or whole-file semantic conformance.
The MRR-owned plan must perform final result admission. Full reference scans also
check every source row against its offset partition. Arbitrary property groups,
incoming layouts and property paths remain separate acceptance slices.

The same Backend runs source preparation and outgoing reads with distinct
retained leases; checks run between verification files/chunks and before return.
The source reservation covers at least declared bytes; the Host separately
estimates index/decompression/conversion overhead. Cooperative stop does not
interrupt a running native/Parquet call. Fixtures cover two vertex partitions,
edge chunk boundaries, duplicates with distinct FactIds, self loops, zero degree,
unknown entities, source deletion, stale scope, bad CID/negative/truncated offsets,
pre-/mid-chunk cancellation, deadline refusal and fresh retry, parallel positional
