This slice follows PR #12 at =b3e29acb09d4d014fd6a4efe9bee5a11391e92f5=,
which delivered the local publication process-exit matrix. New selective-source
acceptance is recorded below; remote acceptance remains a separate exact-head

remain =0.8.1=; Cargo build parallelism remains the default.

* Architectural decisions retained

- MRR owns canonical identities, catalog, graph-query semantics and result admission.
- GraphAr is the provider-independent physical graph foundation for Production
  graph workloads, including topology, adjacency/offsets and property groups.
- Arrow provides typed interchange; the shared Backend owns one Host runtime
  lifecycle, admission, leases, publication/recovery and drain.
- Native Turso/DuckDB are optional transaction/execution providers. Engine
  tables, indexes and extension CSR state are derived images of verified sources.
- DuckGQL is a separately gated extension, not native DuckDB graph capability.
  Its availability and benchmarks do not gate GraphAr persistence/selective access.
- Production owns the common contract; no Example, profile-specific runtime or
  reverse dependency changes that ownership.

See [[file:0001-mrr-data-plane.org][the canonical data plane]], [[file:shared-backend.org][shared Backend]],
[[file:../rfcs/0002-graphar-arrow-backend.org][RFC 0002]] and [[file:../rfcs/0003-gql-duckdb-turso-backends.org][RFC 0003]].

* Findings that change the execution plan

** Delivered slice: queued explicit stop

The queued stop slice is now implemented. =ResourceControl= has a sticky
notification and the dispatcher races both resource/shared permit waits against
explicit cancellation and the Host-clock deadline. It drops owned request input
and its reservation before returning a typed stop. The held-worker fixture
covers both lanes without releasing the held worker, including a future deadline
and a live explicit-cancel waiter. Running native calls still retain admission
through cleanup; queue timers do not assert native interruption.

** P1: ownership budgets are contractual, not a physical memory ceiling

=ResourceHandle::get= borrows a value but cannot prohibit callers from cloning
=PhysicalQueryOutput=. MRR projection currently consumes an owned output, and
source captures use shared decoded facts. Keep the lease through conversion and
admission, and explicitly reserve conversion/candidate scratch or transfer
accounting to another owner before exporting clones. Do not describe logical
reserved bytes as native RSS or as enforcement over arbitrary Rust clones.

=ResourceHandle::try_transform= now consumes unique ownership and carries its
existing lease into the converted representation. Shared handles are refused
without running conversion; conversion failure releases admission. The native
Turso fixture consumes physical output into an MRR candidate, admits it and
keeps the candidate lease through drain, without cloning the physical result.
Host conversion scratch is still explicitly budgeted. This provides a library
handoff receipt, not a deployed Host invocation.

Qualify that handoff through a simulated Host caller before broadening results;
include a retained clone and conversion overlap, not only handle-drop tests.
A borrowed/consuming lease-aware conversion API should be selected from actual
MRR caller requirements rather than introducing a second result model.

** P1: GraphAr strategic role requires a selective execution source

Current =CapturedGraphArSnapshot= retains =Arc<[Fact]>= after complete decoding.
This proves immutable bounded capture, not source-pinned adjacency cursors or
selective property scans. Rebuilding an SQL table from all captured facts on
an invocation does not demonstrate scalable graph access.

Deliver a checked outgoing-neighborhood scan for the existing binary-Entity
projection before inventing another query planner. Retain verified chunks and
source binding under the shared Backend lease. Specify source versus destination
layout support, offset bounds, endpoint/FactId mapping and property-row alignment.

Selective reading must preserve integrity: the current inventory/root design
may still require reading every declared file to verify the closure. Record
integrity-verification bytes separately from execution-read bytes. Claim reduced
end-to-end I/O only with a qualified authenticated chunk/cache design, never by
skipping closure validation. Source mutation, stale bindings, malformed offsets
and property/topology misalignment must yield no admitted candidate.

** P2: distinguish current emitter from proposed generalized SQL plan

RFC 0003 describes a future =PreparedSql= and multi-shape typed plan. Current
code exposes =TursoSingleHopSql= for a deliberately narrow fixed mapping. It
has no delivered general SQL plan, property filter, arbitrary parameter mapping
or multiple-engine renderer. Mark the generalized section as proposed and tie
each expansion to an MRR semantic slice and independent expected rows.

** Independent research gate: DuckGQL

Upstream typed-plan entrypoint, extension ABI/binary compatibility and canonical
identity/result ordering require separate prototypes. No qualified bridge is
implemented. Keep that work independent of GraphAr and Turso delivery. Do not
replay source GQL into a second semantic binder to manufacture completion.

* Performance experiment contract

The first experiment compares full capture and selective execution reads of
one published binary-Entity graph. Use independent expected rows, varied degree
skew, isolated cold/warm verification/cache states and identical MRR result
ordering/admission. Measure setup/verification, data bytes, decode/copy, query,
first/total result, retained reservations, actual native RSS and spill separately.
Do not infer peak memory from row limits or infer throughput from build/test time.
DuckGQL comparison starts only when its bridge is qualified; GraphAr delivery
continues without it. Performance results decide optional execution optimizations,
not the physical graph foundation's architectural position.

* Definition of closure

A slice is closed only when its implementation, refusal/lifecycle fixtures,
exact-head platform checks and RFC status agree. Current P0–P2 closure concerns
the framework: simulated Host authorization and original-query callers, native
local providers, and local process/fault injection are sufficient evidence.
Deployment credentials, live Lambda/Marlin processes and deployed object stores
are not prerequisites. Future product deployment requires its own integration
acceptance. General graph-query conformance and hard native deadlines remain
unclaimed until individually qualified.

* Current execution checkpoint

Implemented this slice: queued explicit cancellation/deadline and consumption
of physical output into a leased MRR candidate. Focused resource/native tests,
workspace policy and strict native adapter lint are the local gates. Remote
exact-head acceptance must be recorded separately after publication.

The pinned native bridge remains the maintained writer and full-source reference.
Its safe reader has no vertex/range cursor. Optional =selective-graphar= instead

Host inputs are simulated in this stage. Use the existing Backend authority
CAS for policy/key enrollment, rotation and retirement; serialize final protected
disclosure with those changes in the simulated Host. Historical recovery remains
a receipt lookup, never fresh disclosure permission. Original Lambda/Marlin
query bytes and expected rows can run through local simulated callers.
Publication-phase process-crash fixtures are now implemented below. The ordered outgoing slice is implemented below. Original property-path
expansion and the full cold/warm/RSS performance matrix remain outstanding.

** Simulated Host authority contract

=backend_consumer::authorities::simulated_host_disclosure_rotation_retirement_and_replay_are_separate=
uses the existing native Backend with a local simulated Host. It enrolls separate
policy and key commitments, binds both to a fresh content effect, refuses omitted
or stale guards, rotates the key, and orders final disclosure before concurrent
policy retirement. Canceled pending disclosure emits nothing. Historical replay
and exact receipt recovery remain available after retirement, while disclosure
is refused both before and after native reopen.

All mutations and final disclosure pass through one simulated Host boundary.
This qualifies that single-Host contract; it does not claim that a local mutex
coordinates independent processes or that Backend CAS alone authorizes payload
release. A future distributed Host supplies its own equivalent final-disclosure
coordination. No live credential or deployed service is needed for this fixture.

Local simulated-Host acceptance: the same consumer passes with native Turso
=0.8.1= and DuckDB; strict Backend consumer clippy (=--profile test=,
=-D warnings=), formatting and diff checks pass. Remote acceptance of the new
commit remains a separate exact-head CI gate.

** Publication process-exit matrix

=backend_graph_publication::publication_process_exit_preserves_original_operation_and_complete_head=
runs a native provider in an independent child process and exits without Backend
shutdown or Rust destructors at eight boundaries: first child write before ACK,
inventory write before ACK, snapshot write before ACK, before binding-root upload,
root write before ACK, complete publication ACK before CAS, before provider CAS,
and after native commit before returning its receipt. Each child has a 30-second
watchdog; its exit code must identify the configured fault rather than a passing
or accidentally failing harness.

The parent seeds an existing head and policy guard, reopens native state, and
recovers only the original operation. Before commit it requires confirmed
absence and an exact-prior-head retry; after commit it requires the exact next
revision and validator-free replay. Cold restore reads file-backed simulated
remote blocks and requires root, block count and byte-count parity. Incomplete
child/metadata closure is refused; a root written before a lost ACK remains
restorable but does not advance the selected head.

This qualifies local process exit at publication/provider boundaries with opaque
transport fixture bytes. Native GraphAr/Arrow format qualification remains in
its separate facade consumer. It does not interrupt the native COMMIT call or
attest power loss, filesystem/object-store durability across machine failure, or
independent deployed services. Existing =backend_consumer= uncommitted-transaction
process-exit fixtures cover a separate native metadata rollback boundary.

Local receipts for this matrix: native Turso =0.8.1= and DuckDB graph-publication
suites each pass four harness tests, including all eight child exit points.
Strict consumer clippy (=--profile test=, =-D warnings=), Org links, formatting
and diff checks pass. Exact-head Linux/macOS CI remains pending; these local
receipts do not close the P0 platform acceptance gate.

** Ordered outgoing snapshot source and matched physical work

=GraphArSelectiveSnapshot= authenticates the query/binding/projection, copies
and CID-verifies every declared inventory file, admits the native vertex index,
and reads ordered offsets once. It checks first offset zero, nonnegative monotone
offsets, real vertex tail and padded tail equal the declared edge count. It then
opens read-only topology/property descriptors and deletes the private directory
before returning. Original-directory mutation/deletion cannot change retained
bytes. The final handle closes descriptors without deferred recursive deletion.
Linux/macOS are the qualified platforms; unlinking open files is not claimed
as a portable Windows lifetime contract.

Outgoing access uses positional reads, cached offsets, row selection and boundary
probes. It validates selected source IDs, endpoint bounds, exact topology/property
row counts and fields, canonical identities, FactId uniqueness within the slice,
projection and generation. It rejects shifted/truncated offset intervals rather
than accepting incomplete neighborhoods. A selected slice is physical MRR facts,
not a whole relation, a general query result or whole-file semantic conformance.
The MRR-owned plan must perform final result admission. Full reference scans also
check every source row against its offset partition. Arbitrary property groups,
incoming layouts and property paths remain separate acceptance slices.

The same Backend runs source preparation and outgoing reads with distinct
retained leases; checks run between verification files/chunks and before return.
The source reservation covers at least declared bytes; the Host separately
estimates index/decompression/conversion overhead. Cooperative stop does not
interrupt a running native/Parquet call. Fixtures cover two vertex partitions,
edge chunk boundaries, duplicates with distinct FactIds, self loops, zero degree,
unknown entities, source deletion, stale scope, bad CID/negative/truncated offsets,
pre-/mid-chunk cancellation, deadline refusal and fresh retry, parallel positional
reads, saturated resource budget and last-clone shutdown drain.

The ignored =selective_matched_workload_experiment= compares the same verified
snapshot and canonical index against a full Rust scan and an independent full
native read: 4,096 facts, 64 vertices, 128-row physical chunks, uniform and skewed
degrees, two warmups and 21 measured repetitions. CI runs it on both OS and
asserts exact facts plus reduced read bytes/materialized rows, without a timing
threshold. Local macOS receipt:

** P0 cache removal-race repair

Exact remote head =868a9b9fc4e38cf26adbb29da51fda97a7b540b9= failed Linux
workspace acceptance in =upstream_maintenance_and_removal_races_recover_and_reopen=:
=Content(Io { operation: "get Kache entry", kind: NotFound })=. Pinned upstream
Kache checks metadata presence before opening it, so concurrent removal can
return a contextual I/O =NotFound= between those operations. The content adapter
now maps this typed case to =ContentError::NotFound(cid)= and preserves other
errors. Read-through can recover verified remote bytes; no permissive fallback
for permission/corruption errors is introduced. The existing removal/maintenance
race and a contextual-error classification fixture qualify this correction.

Local acceptance for this implementation: complete GraphAr selective/Backend
suite (36 passed, two explicit experiments), strict all-target GraphAr clippy
with =--profile test -D warnings=, and five Kache blocking acceptance fixtures
pass. Cargo parallelism remains default and all nine Turso pins remain 0.8.1.
These receipts do not substitute for the new commit's exact-head remote checks.

The new matched range-read experiment passes. The existing native 10k Scenario
is not locally closed: during a concurrent native build the paired 5% median
saving gate failed; after this task's build ended that paired gate passed, while
prepared admission P95 was =63.974334ms= against the unchanged =50ms= cap
(P50 =271833ns=). Bridge total P95 =374.460709ms= and semantic-read P95

** P2-B: bounded prepared projection reuse and process resource measurement

Prepared sources now hold at most one successful physical-projection certificate
shared by their clones. Its key is the complete admitted relation schema and
optional catalog digest; a different key revalidates every immutable fact and
cannot overwrite/grow the cache. Failed admission never certifies. This removes
repeated row validation for the same prepared source/projection, while fresh
Host effects/disclosure and final MRR query-result admission remain mandatory
at their own owners. A new source has a new certificate, and snapshot/generation
scope checks are unchanged. Cold/first validation is distinct from measured
warm reuse; no old measurement is relabeled as a cached result.

=GraphArSelection::into_facts= additionally transfers its existing Vec under
=ResourceHandle::try_transform=. The fixture verifies allocation identity,
reservation retention and final-clone drain. Public immutable access still does
not enforce RSS over arbitrary caller clones.

The opt-in Rust =graphar_range_workload= benchmark adds eight process-separated
cases over uniform/skewed 65,536-edge native fixtures. It records normalized OS
RSS high-water at baseline/preparation/first query/reuse, CPU, page faults,
block operations and involuntary context switches. Native full parity runs in
the parent; each child compares an independent full Fact-context/value digest
for its outgoing result. Two warmups and 21 measured reuses share one verified
source; no child retains the producer's fact vectors. The supervisor enforces
paired digests/counts and lower reader bytes/Arrow materialization, and kills
silent/stalled children. It does not impose a latency/RSS reduction threshold.
The [[file:../../crates/mrr-data-graphar/benches/README.org][benchmark contract]] distinguishes fresh processes from uncontrolled OS caches,
cumulative high-water from current allocations, and diagnostics from engine
spill. Linux/macOS CI runs the experiment; local measurements follow below.

** P2-A: native catalog-declared entity property mapping

MRR Data now has a native string entity-property writer/capture API and optional
shared Backend composition. It retains empty types and isolated entities,
canonical global entity identities, exact declared nullable property shapes,
and owned Arrow tables. Inventory capture uses the existing private CID-verified
copy mechanism; caller YAML never chooses native paths. Local receipts and
retained reuse bind full catalog, generation and semantic snapshot digest,
including refusal of changed revisions within the same generation.

The physical acceptance restores entity properties and both path relations
through native GraphAr, removes their source directories, feeds the owned Arrow
tables through the existing Healthcare-shaped two-hop executor, independently
compares expected rows, and runs MRR result admission. Additional fixtures cover null/empty/Unicode,
empty types, corrupted inventory content, unsupported scalar schemas, aggregate
budgets, canceled preparation, consuming allocation-preserving table transfer,
and shared Backend final-clone drain. These fixtures use admitted IR and do not
claim original GQL compilation or Lambda invocation. The property artifact now
has a canonical DAG-CBOR descriptor/CID with no serialized local paths. Decoder
admission verifies bytes, version, unknown-field refusal, limits and the caller
admitted catalog. A separately launched process reopens the native property
files from the descriptor and independently compares every canonical row under
a five-second gate; its fixture CID simulates publication authority. Global
SnapshotManifest/profile root registration and MRR-owned original-source handoff
remain integration slices.
