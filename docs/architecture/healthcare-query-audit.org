#+title: Healthcare original-GQL property query audit

* Source and ownership

The maintained Healthcare source is the Lambda Episteme
=case-profile-relations.gql= query. MRR's parser-owned frontend test fixture and
this repository's worker acceptance fixture have identical bytes and SHA-256
=7a3a88a9ebd24cd738d426c0def633247d1a0fc13e9e37cca13bb23e90ba0c63=.

#+begin_src gql
MATCH (s:Scenario)-[:HAS_CASE]->(c:Case)-[:HAS_EFFECTIVE_PROFILE]->(p:Profile)
WHERE s.identity = 'healthcare'
RETURN s.identity, c.id, p.identity
#+end_src

POO Flow/Lambda owns Scenario, Case, Profile and the two relation projections.
MRR and gerbil-parser own GQL compilation, label-to-type identity, catalog
binding and result admission. MRR Data owns only immutable snapshot transfer,
Arrow IPC verification and bounded physical execution. The static-edge worker
profile remains unchanged.

* Implemented library path

=mrr-data-poo-flow::materialize_property_snapshot= accepts MRR-admitted
catalogs and semantic generation, typed source rows, caller-owned coverage
evidence, and physical budgets. It verifies the complete catalog table set,
property shapes, unique entity identities, relation endpoints, coverage CID,
source string budgets before encoding, and encoded block sizes before storing
deterministic Arrow IPC children and the immutable CID root. It does not infer
labels, claim source completeness,
or define a second GQL parser. Remote publication remains the existing
=mrr_data_content::publish_snapshot= path.

=mrr-data-poo-flow::execute_property_source_worker_query= accepts the original
source and digest, admitted entity/relation catalogs, a CID root, transfer
session and independent transfer, execution and result limits. It restores a
complete content closure, compiles GQL through =mrr-frontends=, binds the MRR
query to the restored semantic snapshot, binds the physical root, executes the
property path in DataFusion, and submits the candidate to MRR admission.

The worker does not infer type IDs from label strings. Its caller must supply
catalogs whose identities agree with the MRR frontend. Tests derive their
catalog identities from the compiled query IR, so a frontend namespace change
cannot silently make the fixture a parallel authority.

* Evidence and remaining gate

On 2026-09-23, the focused macOS =just test-property-query= suite passed 12/12
tests. It includes exact-source digest rejection, deterministic producer
materialization, failed catalog/endpoint/coverage admission, a cold/warm
restored-snapshot test with the same admitted result digest, and the full
typed-row producer to remote publication to original Healthcare GQL worker
path. Existing
DataFusion tests cover malformed IPC, row-count and catalog substitution,
resource limits, dangling endpoints, null properties and multiplicity.

The original-GQL property worker and S3/Kache transport passed Ubuntu and
macOS in [[https://github.com/tao3k/mrr-data/actions/runs/35851110524][CI run 35851110524]], which also passed the snapshot distribution
acceptance gate. The change was [[https://github.com/tao3k/mrr-data/pull/2][squash-merged in PR #2]]. This is cross-platform
library and transport acceptance, not application invocation evidence.

The actual Lambda/Marlin process has not yet exported its projected POO rows
through a typed native boundary or called the property producer/worker. A
deployed S3/Kache provider serving the same root and a release-qualified host
invocation also remain separate gates. The caller owns a wall-clock deadline
and cancellation across restoration and query execution; neither is supplied
by this library test.
