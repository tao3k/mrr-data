* MRR-owned dispatch into the Data backend — implementation slice

MRR's contract facade owns =PropertyQueryBackend= and
=CatalogBoundQuery::execute_with=. MRR Data's =RestoredPropertyBackend=
implements this port with the original admitted query, verified immutable
snapshot, original relation/entity catalogs and physical execution limits.

=project_data_query_output=. MRR then admits the returned candidate against
its original query and result limits. Backend success cannot bypass this
final admission. Physical evidence retains the selected root and engine.

Data's dependency disables the facade's default inference feature. No parser,
Scheme SDK or native solver is a dependency of the ordinary Backend build.
Production MRR selects native Scheme inference separately. Data owns Backend
and Protocol implementation; MRR owns dispatch and semantic admission.
The restored backend currently uses already verified restored content. This
slice does not add remote dispatch, retries, cancellation, provider admission,

The new executable controls cover actual restored DataFusion dispatch,
corrupt IPC rejection, query/physical generation mismatch, and MRR result

query fixture; source compilation remains in MRR. Tests do not reconstruct
