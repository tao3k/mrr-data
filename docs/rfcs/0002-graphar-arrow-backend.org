#+TITLE: RFC 0002: GraphAr, Arrow and the Shared Production Backend
#+OPTIONS: toc:2

* Status and scope

Status: proposed; implementation gates below distinguish current code from
planned capability. Written 2026-10-03 against the MRR Data interfaces at
=8704d46a7c4d2af3749726dac3e583a3d1725c50=. This RFC extends
[[file:../architecture/0001-mrr-data-plane.org][RFC 0001]] and [[file:../architecture/shared-backend.org][the shared Backend contract]]. It covers all Production
profiles using graph snapshots, rather than one Example or application.

[[file:../architecture/arrow-execution-practices.org][The Arrow performance audit]] binds official guidance and the exact GitHub SDK
source to code decisions and falsifiable performance gates.

The design uses one Host-owned Backend lifecycle with optional physical
capabilities. GraphAr owns immutable graph projection storage, Arrow owns typed
interchange, and DuckDB owns optional native execution. Existing metadata
providers remain responsible for atomic head/operation/authority transactions.
The graph file format alone cannot replace that transaction contract.

* Current interfaces and specific gaps

| Interface | Implemented today | Remaining gate |
|-----------+-------------------+----------------|
| =BinaryEntityProjection= | Admits exactly two non-null Entity endpoints | Explicit profiles for property-bearing or reified relations |
| =write_graphar_dataset= | Native graph metadata, Parquet chunks, stable semantic properties | Bounded, content-addressed publication of the complete dataset |
| =GraphArQuerySource= | Root path, relation, endpoint roles, identity properties and counts | Generation/catalog identity plus a verified immutable child inventory |
| =prepare_graphar_source= | Imports native Arrow C Stream batches, validates and materializes facts | Streaming admission with bounded buffers; preparation currently retains facts |
| =admit_graphar_query_source= | Re-hashes =mrr.graph.yaml= against the bound projection CID | Protect all referenced metadata and data chunks, including read-time drift |
| Shared =Backend= | Independent write/recovery/resource admission and dispatch; resource handles join owned drain | Fallible streaming Arrow query execution and measured native memory bounds |
| =CapturedGraphArSnapshot= | Authenticated binding/inventory, private verified copies, catalog-bound fixed schema, immutable facts | Additional graph profiles and streaming native buffer ownership |
| Optional DuckDB | Local metadata transactions; this change enables and tests native Arrow capabilities | A public bounded graph/query port using the shared dispatcher |

The current graph-info check authenticates the entry metadata bytes. It does
not hash every referenced chunk and does not seal a mutable filesystem path
against a subsequent replacement. A =GraphArQuerySource= or prepared fact cache
must not be treated as fresh authorization or complete physical integrity.

* Ownership and feature composition

| Owner | Responsibility |
|-------+----------------|
| MRR | Relation/Entity/Fact identities, semantic generations, catalogs, query admission and candidate-result admission |
| MRR Data core/content | Snapshot descriptors, content identity, publication ACKs and verified immutable reads |
| MRR Data GraphAr | Declared projection, native graph file mapping, chunk traversal, Arrow import, physical validation |
| Shared Backend | Admission, retained-resource accounting, owned tasks, provider composition, drain and metadata commit/recovery |
| DuckDB/DataFusion adapters | Engine-specific registration/planning/execution, typed batch limits, rebuildable caches |
| Host | Runtime lifetime/capacity, credentials, policy commitments, operation validation and final disclosure |

=backend-duckdb= implies =backend= and =arrow=. The DuckDB SDK enables
=appender-arrow=, which also enables =vtab-arrow=; Arrow results are supplied by
the pinned SDK. Rust Arrow types use the workspace's Arrow 58 family. The optional =DuckDbArrowInput= carrier checks native vector capacity, explicit
row/buffer limits, unique nonempty field names and the qualified Int64/Utf8/Binary
subset before registration. It grants no semantic authority or Backend lease.
The generic
Backend and =backend-turso= do not opt into DuckDB or this Arrow capability.
=backend-graphar= composes the same Backend with native graph capture; it does
not select a database. =graphar= remains a portable projection contract; =graphar-native= opts into the
pinned C++ provider. GraphAr never depends on DuckDB. Engine composition stays
above the physical graph format and adds no provider-owned runtime.

* Projection and identity contract

The first qualified profile remains binary Entity-to-Entity. Endpoint roles are
explicitly named in the admitted relation; native vertex positions and adjacency
orientation cannot infer those roles. Duplicate endpoints are allowed when
=FactId= differs. Duplicate facts, missing/dangling endpoints, mixed relations,
unsupported types and ambiguous physical-to-semantic mapping fail closed.

Preserve =EntityId=, =FactId=, =RelationId=, =GenerationId=, authority,
provenance, completeness and validity through export/import. The current writer
already emits these semantic properties; new readers and batch paths must retain
them. GraphAr vertex/edge row IDs, chunks and offsets remain physical identities.
An ordinary property table is not the complete-Fact Arrow profile. Reification
of n-ary relations and nullable or non-Entity endpoints requires a separately
versioned, lossless MRR-owned projection contract before enabling it.

* Dataset manifest and verified reads

Propose a versioned GraphAr dataset manifest composed with the existing snapshot
manifest. Its canonical body binds:

- semantic snapshot generation and admitted catalog digests;
- projection namespace/version, relation identity and endpoint roles;
- metadata entry CID and a complete metadata/data child inventory;
- each child's relative logical path, role, content CID and encoded byte length;
- vertex/edge counts, property schema, file codec, adjacency orientation and
  chunk sizes sufficient to validate the declared projection;
- aggregate encoded-byte, row, child-count and open-handle limits.

Paths are relative logical identifiers: reject absolute paths, parent traversal,
backslash ambiguity, duplicates and filesystem aliases escaping the admitted
root. The manifest cannot list itself. Duplicate or unavailable children,
unknown required fields, unsupported codecs and mismatched lengths/CIDs refuse
admission. A schema or manifest version change is explicit; do not reinterpret
an existing V1 snapshot in place.

Native GraphAr currently reads paths. A provider must first materialize verified
children into an owned immutable local snapshot, then open native handles there.
Verify the exact bytes used by native I/O; hashing a path and reopening that
mutable path is insufficient. A production implementation must qualify its
platform-specific sealing/handle strategy against concurrent replacement.
Retain the snapshot lease while queries or Arrow export buffers depend on it.
Metadata-only admission remains available with its current bounded claim until
the full verified-read gate passes.

* Publication and recovery state machine

1. Admit the projection and catalogs, and reserve bounded graph work in the
   shared Backend before allocating native builders or staging files.
2. Write into a unique owned staging root. Freeze metadata and chunks, verify
   all semantic and physical invariants, then construct the canonical child
   inventory and dataset manifest.
3. Publish immutable children first, followed by the dataset manifest. Require
   ACKs for the configured durability contract; a local file close alone is not
   a remote or power-loss receipt.
4. Submit the manifest CID through the shared protected head/operation commit,
   with exact expected revision and applicable authority generations. SQL and
   provider transactions remain adapter details.
5. Report success only after both required physical publication and metadata
   commit. If ACK/COMMIT is ambiguous, report Unknown and recover the exact
   operation identity. Never infer failure and issue a new operation ID.
6. Historical replay verifies the same request body and returns its original
   receipt, without granting fresh publication/query/disclosure permission.

Crash after child publication can leave unreferenced immutable objects. These
are reclaimable only through a later bounded reachability policy that respects
active snapshot leases, retained generations and recovery history. This RFC
does not enable automatic deletion or reset. Cancellation before validation
refuses new content; accepted administrative work and validated commit/drain
stay owned under the existing lifecycle contract.

* Arrow execution and resource contract

Use typed =RecordBatch= boundaries between GraphAr and native engines. Inputs
carry admitted schema/catalog identity and an immutable snapshot lease. Validate
all types, nullability, semantic metadata and buffer/row limits before native
registration. Physical columns are translated by declared projection mapping;
engine column names cannot supply missing semantic roles.

DuckDB input slicing is lazy and validates the retained source once. Native
Rust VTab conversion still copies values; Python/R Arrow zero-copy guidance does
not qualify this path. The future port must provide a fallible terminal result
contract, because the pinned SDK iterators do not expose late fetch errors as
Result items. Native scan pushdown, memory/thread limits and materialization
behavior have distinct qualification gates in the performance audit.

DuckDB may register bounded Arrow input or append into rebuildable staging
relations and return Arrow results. A bulk appender does not establish protected
metadata CAS, authorize the query, or make partial output publishable. One
connection's transaction must encompass any staging mutation; flush is followed
by the required commit or rollback. Native SDK buffers and prepared state have
explicit owners until no consumer can access them.

The future graph/query port must use the shared admission and dispatcher,
retain queued request/batch resources, and track row/buffer/native-handle budgets.
Do not call native work directly from async code or allocate an independent
runtime. Graph readers, Arrow buffers, temporary files and database caches need
separate measured budgets: current =retained_bytes= covers requests, not total
native RSS. Limit defaults are selected from measurements, rather than inferred
from GraphAr's empirical chunk defaults. Recovery capacity remains reserved.
Drain seals new work and waits for accepted graph jobs and leases before closing
native state. The exact policy for externally retained result buffers must be
qualified before the public port is released.

Returned engine results remain MRR candidates with the bound semantic generation
and coverage. MRR performs final candidate admission; the Host performs any fresh
protected disclosure check. Prepared Arrow/GraphAr data is reusable physical
state, not reusable authority.

* Implementation slices and acceptance gates

| Slice | Code seam | Required executable evidence |
|-------+-----------+------------------------------|
| A: DuckDB Arrow features | Workspace dependency and facade feature graph | Shared Arrow types; 4,097-row append/query/reopen; null/empty/Unicode/BLOB preservation; rollback; virtual Arrow input; no-provider isolation |
| B: Dataset manifest | Core/content descriptors and GraphAr writer receipt | Canonical decode/encode; complete child inventory; duplicate/path/CID/length/codec/limit refusal; preserve existing snapshot versions |
| C: Verified native snapshot | GraphAr preparation plus content-store adapter | Tampered chunk, metadata drift, missing child, alias traversal, replacement race, generation/catalog mismatch all refuse before engine registration |
| D: Publication composition | Existing ProfilePort protected commit/recover | Authority retirement race, historical replay, canceled caller, lost ACK and crash at every publication phase; no partial head advance |
| E: Shared Arrow query port | Backend dispatch plus optional engine adapter | Read/write pressure, cancellation, buffer lease lifetime, busy drain, overload counters and exact post-reopen results |
| F: Performance qualification | Existing GraphAr phase timings and matched query fixtures | Equal facts/results, separate native I/O/C Stream/semantic admission/planning phases, varying chunks/guards, cache/RSS limits and both OS native receipts |

The pinned SDK virtual-table callback copies a complete input batch into one
native vector. A direct 4,097-row probe reproduced =data.len() <= capacity()=
failure followed by a non-unwinding FFI panic and process abort. The public input
carrier reads native capacity using the SDK safe API and rejects over-capacity
batches before that callback. Qualification then queries the complete 4,097-row
fixture in admitted vector-sized slices, preserving order and all values.
Appender qualification keeps the original unsplit 4,097-row fixture, since that
separate SDK path handles vector splitting. A caller using raw SDK APIs can still
bypass the carrier; the future public port must require it, aggregate buffer
leases and bounded scheduling.

Slice A is implemented. Slice B now has a standalone core file inventory under
=content-identity=: =mrr.graphar.file-inventory.v1= uses a DAG-CBOR root and RAW
SHA-256 child CIDs, deterministic path ordering, exact declared lengths and
borrowed-payload verification. Decode checks the encoded-byte budget and root
before parsing, then refuses unknown fields, unsupported versions, unsafe paths,
duplicate paths, wrong CID codecs, total-length overflow and noncanonical order.
Distinct logical paths may share a CID; declared bytes still count per path.

The initial portable path profile admits lowercase ASCII letters, digits,
=._-= and relative slash-separated components. It rejects traversal, platform
reserved names and aliases such as backslashes or drive prefixes. This profile
is narrower than the GraphAr format; native producers must explicitly meet it.
File/path/count limits bound declared inventory work; encoding checks the byte
budget after serialization and does not promise a pre-allocation byte cap or
native engine RSS bound. Empty physical payloads are refused by this profile.

The controlled native writer now enumerates its staging directory before rename
and returns the inventory in =GraphArDatasetReceipt=. =file-inventory= is an
optional adapter feature without the native SDK; =native-graphar= composes it.
Streaming SHA-256 uses a fixed 32 KiB scratch buffer, bounds remaining declared
bytes while reading and checks file count plus a traversal-entry budget of twice
=max_files= (directories included). YAML, native count names and Parquet chunk
names follow the pinned writer profile; count width and Parquet =PAR1= framing
and footer metadata bounds are checked. Framing does not prove a valid Parquet schema or row layout.

Directory re-verification compares exact paths, types, lengths and CIDs, refusing
changed, missing or extra files. Symlink entries and Unix hard-linked files
refuse at observation time. This is an observational receipt, not a filesystem
seal: replacement between inspection/open/hash/rename remains possible. Native
writing precedes inventory checks, so these limits do not cap native writer RSS
or bytes already written to staging. Explicit writer limits allow larger
qualified datasets without replacing the default manifest budgets.

The writer's existing metadata uses an absolute committed prefix, so its exact
metadata identity remains location-specific. A separate
=mrr.graphar.dataset-binding.v1= DAG-CBOR root now binds the inventory root,
snapshot root, generation, semantic digest, relation/entity catalog digests,
relation ID and entry metadata CID. The existing V1 graph descriptor retains its
RAW metadata binding. The Host must authenticate the new binding root through
publication authority; constructing a candidate from V1 metadata alone does not
authenticate data chunks.

=BinaryEntityProjection::admit_catalog= admits the relation from its complete
catalog. Capture requires that catalog digest to match the bound query. Before
native I/O, =capture_graphar_snapshot= verifies the binding and inventory, copies
only declared files with bounded streaming CID/length checks into a private
random directory, and checks the copied count/Parquet framing. Only declared
paths are created; files are hashed once during copy, with no second full scan. Native GraphInfo
uses the fixed binary-Entity writer schema with a private prefix. Authenticated
YAML bytes are preserved but never interpreted as path instructions, so external
YAML references cannot redirect this entry point. This qualifies the fixed writer
profile, not arbitrary GraphAr metadata import.

After native preparation, every fact must pass the admitted projection and match
the binding's generation. Immutable Rust fact buffers are exposed only through a
query-scope check. All native handles are gone and temporary files are removed on
the preparation worker before a successful return. Source deletion or mutation
cannot change these facts. This is a captured semantic snapshot, not an OS
sandbox or a streaming Arrow query engine; existing legacy readers remain mutable
path entry points.

The =backend= feature in the GraphAr adapter composes this capture with
=Backend::prepare_resource=. It uses shared count/byte admission, independent
resource worker slots and the same Host runtime. Queued cancellation skips work;
submitted native work keeps its lease until completion. Cloned ResourceHandles
retain the reservation until final destruction; shutdown refuses new work and
waits for these handles before closing metadata providers. The Host reservation
must cover declared physical bytes and separately budget native decompression
and fact materialization. It does not measure or cap native RSS.

Slice C is implemented for captured binary-Entity facts. Slice E has shared
resource lifecycle support; a fallible streaming Arrow query port remains open.
Slice D now implements complete closure preparation, child/root ACK ordering,
cold restoration and the typed protected ProfilePort composition described below.
Process/power-loss injection at every phase, additional profiles and matched
performance/RSS qualification (F) remain open.

The implementation and malformed-wire qualification are in
[[file:../../crates/mrr-data-core/src/graph_inventory.rs][the core inventory]] and [[file:../../crates/mrr-data-core/tests/unit/graph_inventory.rs][its focused tests]], with [[file:../../crates/mrr-data-graphar/src/inventory.rs][directory enumeration]] in the GraphAr adapter.

* Alternatives and decisions

- Use GraphAr as an immutable physical capability under the shared lifecycle.
  It lacks the metadata transaction semantics required to act as a replacement
  =TransactionProvider= on its file-format guarantees alone.
- Use Arrow for input/output and semantic profile boundaries. Durable graph
  chunks keep their qualified GraphAr codec, initially Parquet; Arrow IPC is
  not silently relabeled as a GraphAr physical format.
- Keep one lifecycle and explicit provider capabilities. Query-engine indexes,
  CSR caches and prepared plans are rebuildable state with generation keys.
- Reject undeclared graph projections. A guessed generic conversion can lose
  relation arity, Fact identity or authority/provenance meaning.

* Complete graph publication and protected recovery

=backend-graph-publish= composes the generic Backend and the portable content
=graph-snapshot= feature. It selects no native GraphAr SDK, database, cache or
network provider. =backend-graphar= independently enables immutable native
capture; an application selects both when it needs capture and publication.

[[file:../../crates/mrr-data-content/src/graph_snapshot.rs][The graph closure protocol]] verifies the binding, inventory, legacy snapshot,
complete catalogs, every referenced child CID and declared byte length before
any remote PUT. Count, per-block and aggregate logical payload bounds include
all three roots. Identical CIDs share one stored payload. Preparation currently
materializes the closure; these bounds do not establish native RSS or streaming
performance. A disk ContentStore must execute on the Host blocking executor.
The same =Backend::prepare_resource= holds its reservation until final handle
destruction; retain that handle throughout publication and protected CAS.

Publication ACKs ordinary children first, then inventory and legacy snapshot,
and finally the binding root. =GraphPublication= has private construction and
is returned only after every ACK. A fresh before-root callback is distinct from
synchronized authorization: the Host's root transport must hold the actual
policy guard throughout PUT. A later [[file:../../crates/mrr-data-backend/src/graph_publication.rs][ProfilePort::commit_graph_publication]]
requires the matching receipt, current enrolled authority generations and fresh
validation inside the existing protected metadata transaction. Failure or
cancellation may leave immutable orphans; it neither deletes shared content nor
selects a head. No new provider runtime or metadata transaction engine is added.

After an uncertain metadata COMMIT, recover the original operation, expected
revision, replacement and authority expectations. Exact historical replay can
omit publication and skips new validation. It conveys the original receipt and
grants no fresh content or disclosure permission. Restoration starts from a
Host-authenticated binding root and verifies the entire bounded closure again;
it does not discover or authenticate the latest head by itself.

[[file:../../crates/mrr-data-content/tests/integration/graph_publication.rs][Transport tests]] cover every block ACK failure, final ACK loss and exact CID
retry, denied/cancelled root gate, cold restoration, tampered children, absence
and aggregate limits. Opaque payloads qualify transport integrity; native graph
format and semantic facts are qualified by the separate capture tests.
[[file:../../crates/mrr-data-backend/tests/integration/graph_publication.rs][Native Turso composition tests]] cover retained resource preparation, missing
or mismatched receipts, fresh policy refusal, complete ACK-to-CAS, retired
versions, original-operation absence/retry, close/reopen recovery and historical
replay without new transport or validation. These are local native restart
receipts, not power-loss or deployed blob durability measurements.
