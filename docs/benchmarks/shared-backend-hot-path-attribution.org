* Reviewed scope and accounting boundaries

Weaver's existing SysML GovernancePolicyProjection was reviewed before these
test-only changes. Preserve [[file:shared-backend-cpu-matched-reuse.org][the original 0.74 reuse/WAL sample]] rather than
claiming to retroactively trace it. No production provider, dependency pin or
qualification package changes. All measurements use the existing provider and
shared logical metadata engine, not another persistence implementation.

Source inspection establishes a crucial distinction: ProfilePort sends a
request from the transaction worker to the async caller, runs the borrowed
validator there and sends its answer back. The original transaction remains
held. The old body residual therefore includes validator work and rendezvous
scheduling; it is not pure SQL CPU time. Keep the borrowed authority guard
alive through commit. Cancellation still does not establish rollback or refund.

The existing public TransactionProvider seam now measures pre-body, body and
post-body with shared timestamps. Their sum must equal the provider total.
A test-only MetadataProvider delegate times the unchanged validation bridge
and forwards every authority/publication method to the existing engine. It adds
no retry, lock, queue or decision. Within the caller's validator, measure actual
bounded file read/CID integrity and decode/equality separately. Every original
request retains lane, attempt, home wait, API duration and validator clocks.

| Quantity | Meaning and limit |
|----------+-------------------|
| Home wait | Existing per-original-home application mutex; hot-domain ordering is unchanged |
| API minus provider total | Admission/dispatch/delivery outside the provider, aggregated over the same successful requests; not semaphore-only wait |
| Pre-body | WAL writer-lock wait or MVCC checkout/configuration, plus BEGIN; not pool mutex alone |
| Physical gets/puts | Native API wall time including query/execute and driver scheduling; not pure CPU or disk I/O |
| Inclusive bridge | Worker request/answer wait including the caller's validator |
| Bridge minus validator | Channel and cross-executor scheduling overhead, including measurement overhead |
| Body minus gets/puts/bridge | Remaining shared-engine logic and encoding; not measured CPU cycles |
| Post-body | FULL COMMIT, autocommit confirmation and physical return/drop; not isolated fsync |

All successful cases assert one body and one validation bridge per original
operation, exact phase decomposition, nested caller clock bounds and exact
operation/authority recovery. Clock aggregation is per transaction; parallel
sums are not wall-clock fractions. No negative residual is silently clamped.

* Reproduced regression: additive attribution

C/1 reproduces the same class of regression more strongly: reuse/WAL=0.685.
Mean per-operation costs below are microseconds; home wait is separate from API.

| Quantity | WAL | Reuse | Reuse minus WAL |
|----------+-----+-------+-----------------|
| Original-home wait | 4656.54 | 6810.99 | 2154.44 |
| API duration | 425.13 | 620.73 | 195.60 |
| Admission/dispatch/delivery outside provider | 10.93 | 80.40 | 69.47 |
| Pre-body checkout/BEGIN | 5.67 | 8.72 | 3.05 |
| Physical gets | 121.71 | 180.17 | 58.47 |
| Physical puts | 82.56 | 93.52 | 10.96 |
| Validator total | 35.54 | 45.69 | 10.15 |
| Bridge minus validator | 10.04 | 75.32 | 65.29 |
| Remaining engine body | 39.96 | 48.03 | 8.07 |
| FULL COMMIT/autocommit/release | 118.74 | 88.87 | -29.86 |

The positive outside-provider and bridge differences explain about 135 of the
196 microseconds API gap in this pair. Gets explain another 58 microseconds;
the cheaper reuse post-body offsets part of the remaining cost. Validator read/
integrity is 32.60/42.09 microseconds and decode/equality 2.72/3.31 for WAL/reuse.
The validator's computation is not the main gap. A single ordered service point
amplifies service-time changes into waiting for the other eleven lanes. Do not
sum independently sampled P95 values as if they formed an additive percentile.

This evidence rules out checkout/BEGIN or COMMIT/release as the dominant measured
cause in C/1. It does not prove that pure pool locking, fsync, or any one scheduler
component can never cause a different regression. The historical 0.74 sample has
no such fine-grained trace and cannot be assigned these exact percentages.

* Sequential public-engine causal control

A separate fixed diagnostic removes ProfilePort admission and request/answer
rendezvous, using the same public MetadataProvider engine, actual file-backed
validator, original mandatory authority vector, home sequence and FULL store.
It runs one transaction at a time while the same CPU-sized runtime services
driver I/O: this is a lower-layer control, not 12-lane end-to-end throughput.
Three rotated rounds retain all 768 operations per variant and every request
duration, then reconstruct a fresh provider and recover each original operation.
It rejects reopening the closed owner. No external send or account refund occurs.

The nine controls add 6,912 commits and exact recoveries. Reuse/WAL total
throughput ratios are 1.22, 0.97 and 1.04; read costs remain about 1.04--1.22x
WAL while cheaper post-body often offsets them. The inline bridge overhead above
validator execution is only about 0.05--0.31 microseconds. Thus the full-path
regression cannot be described solely as intrinsic connection-reuse overhead:
its cross-executor/admission costs matter, and a lower-layer read-path difference
remains. These public native calls include driver scheduling; attributing that
difference specifically to MVCC version traversal needs another native trace.
The sequential control does not justify moving arbitrary borrowed Governance
closures or guards to a worker or bypassing Backend admission in production.

* What is closed and what is not

Closed: the old body accounting conflated borrowed validation and rendezvous;
new real traces reproduce regression, identify its cost distribution and expose
ordered-queue amplification. The trace rejects a connection-setup/FULL-write-only
explanation for the reproduced C/1 pair. A separate control retains the engine's
identity/authority checks while demonstrating a smaller read-path tradeoff.

Open: B/C show broad absolute-cost drift across all modes, consistent with Host
sensitivity, but they do not isolate frequency, background contention, cache state
or scheduler behavior. This is not proof that regressions are merely Host jitter.
The fs_usage probe reports that root is required, so no kernel/device fsync latency
claim is made. FULL COMMIT/release is an inclusive completion measurement and
remains required. Do not relax durability, shard original obligations, retry on
Unknown or default-enable reuse to hide the regression. Keep WAL available for
hot ordered domains; a production scheduler/validator change needs a separate
SysML review preserving borrowed-guard lifetime and cancellation semantics.

* Standard tests, recovery and receipts

The existing benchmark target gains one ordinary nonignored test: execute a real
CPU-sized hot-home workload, assert clock nesting/decomposition and once-only
validation, then reconstruct and exactly recover all original operations. No
synthetic timer-only test or parallel qualification runner is introduced.
The reusable Arrow/query + graph/publication standard suite passes 79 tests;
the WAL-control and fresh-MVCC configurations pass 64 each. The unchanged ASP
deny gate and expanded all-target Clippy pass. Eight opt-in measurements remain
outside those standard correctness counts.
Existing cancellation/retirement/late-return and process-recovery tests remain
unchanged. Their typed original held=4 exposure must persist; free resources do
not authorize a refund. Provider reconstruction and process-death evidence remain
distinct; external final-send, anti-rollback and effective Host revocation retain
their existing SPEC/Host premises.
