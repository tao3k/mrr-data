* Outcome and reviewed contract

No production optimization is admitted in this round. The implementation retains
the pinned Tokio oneshot request/answer channels and original asynchronous
admission task. Both custom Condvar rendezvous and ready-permit dispatch were
reviewed under Weaver SysML, implemented, tested, measured and withdrawn.
Three additional real native guard/rejection/panic tests remain. No dependency
pin, native provider, schema, default mode or qualification package changes.

The callback borrows Host state and runs on the async caller while a worker
holds its original transaction. Eliminating both handoffs by moving it into
spawn_blocking would require static ownership or an unsafe lifetime extension.
block_in_place would block sibling futures within the same polling task and
alter cancellation/composability. Neither is an acceptable default shortcut.

The Condvar candidate carried one revision/request and one irrevocable answer.
Caller drop before an answer refused; published true remained accepted; worker
exit without requesting validation woke the caller. Native lifecycle tests
passed, but added protocol complexity did not earn a stable measured benefit.
The source, frozen binary and failures/regressions are retained temporarily;
the protocol is not included as dead code or a production alternative.

The ready-permit candidate tried the existing worker/shared semaphores before
spawning an admission task, falling back on the original wait path when either
was unavailable. Partial acquisition released permits, not the original
scheduler lease. Both paths released accounting before publishing completion.
Its source-level removal of one task did not establish attributable throughput
benefit; it too is withdrawn. Fairness of registered semaphore waiters is not
global arrival FIFO before registration. Authority order remains the original
durable CAS/home witness, never admission order.

* Native guard and recovery acceptance

The existing lifecycle target now also verifies:

- A callback genuinely borrowing a stack guard executes on the caller thread.
  While native COMMIT is paused, the guard remains live and the original worker
  lease stays active. Only after known completion is the guard dropped; exact
  recovery retains the original claim/reservation/history and held=4 frame.
- Typed validation rejection drains and reconstructs the original unconsumed
  obligation without inventing a new nonce or releasing unknown exposure.
- Validator panic closes the pending answer, lets native cleanup drain within
  the existing bound, and reconstructs the original unconsumed obligation.

Existing queued cancellation, accepted approval with caller cancellation,
known-commit reply loss, retired authority, late-return, simultaneous shutdown
and independent-process crash-recovery tests remain mandatory. Same-process
provider reconstruction is not process death or whole-machine rollback evidence.
No fixture sends to an external provider or executes account-refund arithmetic.

Original-runtime standard validation passes 67 tests in each WAL/fresh-MVCC
configuration, 82 in expanded reusable Arrow/query + graph/publication, and
strict all-target Clippy. No timeout, count, byte or ASP deny limit is relaxed.
Initial ignored-unit-pattern lint failure was fixed without an exemption.
Dependency manifests/lockfile and all production source match the original
after candidate withdrawal. SPEC and existing Lean/Quint ownership do not change;
there is no second authorization model.
