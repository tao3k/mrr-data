* Clocks, nesting and observer limitations

CLOCK_THREAD_CPUTIME_ID uses the existing safe POSIX wrapper. Each CPU span
starts and ends synchronously on one OS thread. Worker body/bridge/post-body,
caller validation and COMMIT are joined by the original scope and operation;
profile and namespace are checked against the workload fixture. Native Rust
rejects missing/duplicate records and invalid causal order. No CPU subtraction
crosses await or task migration.

Bridge wall includes the caller's validation on another thread. Separate delivery,
caller validation and answer intervals; do not add these to bridge wall again.
COMMIT poll wall/CPU and Pending gaps are nested inside total COMMIT. Wall minus
CPU includes both blocking and runnable waiting. Pending is not pure device time.
Process-wide getrusage counters are not individual-operation I/O; Darwin zero
block counters do not prove no I/O. Signed clock residuals remain unmodified.

A test-only forwarding waker records 64 bounded atomic notification slots per
COMMIT and every Pending-to-next-poll window. It forwards all notifications to
the original block_on target, including on observation overflow. A native
concurrent saturation control checks this with max(4, CPUs) callers. Original
waker identity and synchronous OS-thread ownership are asserted.

Classify a window using its first observed notification between poll entry and
next poll entry. A notification before Pending is explicitly early; absent
observations remain unsplit. Other windows separate Pending-to-notification and
notification-to-repoll. A wake is a hint, potentially spurious, not an I/O
completion, durable outcome or authorization. Notification-to-repoll includes
forwarding/glue and runtime/OS resumption; it is not pure runnable latency.
Overflow and unpublished observations remain visible. The pre-proxy and proxy
campaigns cannot be pooled as identical treatments.

* What is now localized

The pre-proxy independent/reuse A1-to-A4 same-binary contrast changes throughput
from 5218/5614/5281 to 11465/10649/9728. Caller CPU remains about 47-57 us;
worker bridge CPU about 6-7 us. Approximately 96-99% of the excess bridge wall
is outside caller validation, and 80-90% of the excess COMMIT wall is in Pending
gaps. This rejects a simple validator-CPU-only explanation; it does not identify
pure Host contention or reconstruct the historical uninstrumented bad request.

The forwarding campaign reproduces substantial drift within the same A4
binary: independent/reuse round 0 to 2 falls from 8862 to 3058 TPS and P95 rises
2.358 to 12.585 ms. Caller CPU changes 54.9 to 60.3 us; worker bridge CPU 7.4
to 7.1 us. COMMIT wall changes 237.6 to 1142.9 us, while COMMIT CPU changes
78.1 to 94.2 us. Pending gaps change 139.7 to 829.6 us: pre-notification
contribution 60.9 to 364.1 us; notification-to-repoll 78.8 to 465.5 us.
Both driver residence and notification/resumption have material excess.
Neither pure query CPU nor pure fsync alone explains these measured wall gaps.

The conditional AV/A direction flips across round/order, and the pre-proxy
late A baseline outperforms early A. A fixed 0.200 multiplier is therefore not
an established intrinsic validator cost. The historical 0.200/11.105 failure
remains valid evidence, not retroactively erased by a faster later run.
The proxy changes observation overhead; it cannot establish its own
performance improvement over the pre-proxy campaign.

* Kernel evidence and remaining obligations

A separate owned-process sample succeeds for A and finds pinned Turso
CommitStateMachine -> DurableStorage.sync -> UnixFile.sync -> fsync plus WAL
sync/pwrite. It also samples preparation's content-store sync_root and idle/hot
workers: whole-profile fcntl/waits cannot be assigned to measured COMMIT.
AV's separate sampler exits 255 because its target has already exited; preserve
that failed observation and its successful benchmark rather than rerun to green.
Sampling itself can pause threads; sampled-leg throughput is not pooled above.
Privileged fs_usage preflight fails without a sudo credential. This never blocks
the run and is not a reason to label all off-CPU time scheduler wait.

Still missing: operation-correlated syscall durations, device completion versus
runnable time, notification provenance for unsplit windows, matched Linux
attribution and a separate O/A admission comparison with the same probes.
The fixed acceptance/nonregression criteria in the host-envelope document are
not met merely by this diagnostic campaign. No timeout, durability mode, retry,
guard ownership or unknown-budget obligation is weakened.

Lean/SPEC retains semantic ownership; Quint retains interleaving ownership.
No second state model is created for clocks. Native cancellation, accepted-work
drain, close/restart, original-operation recovery and retained exposure tests
remain the executable contract gates. CPU/wall evidence is not their proof.
