* Hot-domain regression and causal limits

Reuse beats fresh MVCC in all six matching hot-domain pairs (2.50--3.81x), but
reuse/WAL spans 0.74--1.76x. The B/1 regression is retained: throughput falls
about 26 percent against WAL, P95 grows from 5.96 to 11.45 ms, and P99 from
9.48 to 65.97 ms. Independent B/1 and A/1 also have worse reuse P95 than WAL,
despite higher aggregate throughput. A throughput win does not imply a tail win.

For B/1's hot case, average per-transaction phase costs (microseconds) are:

| Phase | WAL | Reuse |
|-------+-----+-------|
| Physical gets | 120.55 | 155.81 |
| Physical puts | 82.19 | 81.25 |
| Other transaction body | 85.39 | 145.75 |
| Checkout/BEGIN/COMMIT/release envelope | 102.18 | 95.96 |

The reuse envelope is lower while its body and tail are higher. These counters
localize the observed cost distribution; they do not identify a pager, fsync,
scheduler or Host-jitter cause. The body includes actual content validation and
native scheduling. Concurrent phase sums are not wall-clock fractions. There is
no controlled old/new provider comparison here: only test allocation and receipt
metadata changed. Therefore campaign differences and historical ratios cannot
be attributed to another provider optimization.

Keep reuse explicit, preserve WAL for hot ordered domains and select from the
actual domain/tail requirements. Before changing scheduling or storage policy,
obtain a dedicated-Host trace separating validator/queue delay, native calls and
durability I/O with the same original identity and fixed workload. Do not add
automatic mode switching, retries, weaker FULL or home splitting as a workaround.

* Recovery acceptance and remaining premises

The CPU-matched lifecycle target passes five tests covering six schedules:
cancellation before validation, cancellation after validation before COMMIT,
cancellation after known commit with lost delivery, historical replay while its
original reply is pending, effective retirement during validation and competing
pending retirement. Concurrent shutdown uses 12 callers. Fresh providers recover
the exact original operation, authority vector and outbox, keep held=4 and reject
new-nonce attempts under retired authority. Old provider resurrection remains
forbidden. Driver Unknown disposal and late healthy return have separate existing
native owner controls. Cancellation never establishes no-execution or refund.

The standard reusable Arrow/query + graph/publication suite passes 78 tests,
including existing independent-process partial-tuple and graph crash-recovery
cases and the unchanged ASP deny gate. The new lifecycle tests reconstruct a
provider in-process; process-death controls retain their existing minimum-four
runtime profile. These evidence classes must not be conflated. Strict expanded
all-target Clippy passes. No timeout or cleanup requirement is weakened.
WAL-control and fresh-MVCC standard configurations additionally pass 63 tests
each with the same updated lifecycle target. The WAL selector is absent rather
than set to a non-reuse value. Ignored measurements are outside these counts.

The immutable fixture checks retained exposure, not an account-refund algorithm.
Whole-machine rollback, independent retained roots, cross-process credentials,
effective external revocation and Rust final-send currentAtUse remain the
existing Host/SPEC/executor premises. No external send is exercised here.
