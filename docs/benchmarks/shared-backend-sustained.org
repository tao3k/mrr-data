* Implemented observability and deterministic regression

The shared Backend exposes =saturated_writes= and =saturated_recoveries= in
=BackendStatus=. Each counter records lifetime count/byte admission refusal,
saturates at u64::MAX, and starts at zero for each opened Backend instance.
Administrative updates use the write lane. Lifecycle, identity and validation
refusals are excluded. Rejected admission retains no lease or request bytes and
does not increase =completed=. Counters add neither high-cardinality labels nor
clock reads to production requests; both optional providers use this same logic.

Unit checks cover independent lane refusal, byte-budget refusal, unchanged
accepted/retained accounting, successful reuse and lifecycle refusal exclusion.
The native dispatch regression now actually exhausts eight write slots with one
held transaction and seven queued writes. The ninth returns
=BeforeCommit(Saturated)= without calling validation. Historical recovery still
finishes within 500 ms using a Host capped at two blocking threads. The existing
cancellation/owned-drain and 64 single-slot reuse regressions also pass.

* Continuous producer workload

Eight write producers each attempt 64 fresh operations at independent homes;
four readers repeatedly recover an exact historical seed. Write/read admission
is four each, with one submitted worker each. The Host has two async workers and
two blocking threads. Producers synchronize their start, issue sequential calls
per lane, and yield between calls. Saturated writes are recorded without retry.
Readers continue until producers finish, with at least 64 and at most 8,192 reads
per lane. Producer collection has a 30-second failure deadline.

This finite closed-loop workload starts with overload, which can decay as refused
producers finish. It does not hold a constant offered arrival rate, qualify
per-producer fairness or establish an hours-long steady state. The read overlap
counter records calls started while producers remain active, without asserting
simultaneous execution inside both native connections. Records are small and
unguarded; physical block ACKs are synthetic. There is no operation warmup.

Operation timing begins at the port call. Wall throughput excludes seed setup,
reopen and close, and includes producer start/collection. Successful write
throughput counts committed writes only. Saturation has its own latency samples;
its fast failures cannot inflate successful throughput. Reader counts vary with
producer lifetime, so rates are observations of this workload rather than a
paired performance comparison. Table cells are medians of three round-level
statistics; each round's p95 uses nearest-rank individual-operation samples.

* Local gates and remaining qualification

Default backend: four library checks. Turso: four library checks, twelve consumer
cases and three dispatch cases. DuckDB: four library checks, fourteen consumer
cases and three dispatch cases. The one focused Commerce signed-budget
persist/reopen/replay regression passes. Strict all-feature/all-target Clippy,
formatting, diff checks and Org documentation validation pass. Measurements are
opt-in tests and ordinary native CI does not run them. Remote checks must be
reported for the exact published head independently of these local receipts.

These observations do not qualify native cache/RSS budgets, larger guarded
records, long-lived database growth, competing Host executor traffic, actual
block durability, power loss or anti-rollback. Next experiments vary guard count
and bounded record size, then attribute queue/connection/validator/transaction
stages before selecting optimizations. [[file:../architecture/shared-backend.org][The architecture document]] retains the
single Backend, provider and Host ownership boundaries.
