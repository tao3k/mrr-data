#+TITLE: Optional Cedar POO Pseudonymization Binding
#+OPTIONS: toc:nil

This crate is maintained in =mrr-data= and depends on an immutable
=cedar-poo-spec= revision. It enables only the bridge's lightweight
=pseudonymization= feature by default. =google-sdp= is a separate opt-in
feature for Google Sensitive Data Protection request and response types.
Neither feature enables the official Cedar runtime or a cloud SDK.

| Facade feature | Adds | Cedar dependency |
|----------------+------+------------------|
| =data-protection= / =pseudonymization= | Provider-neutral privacy binding | None |
| =pseudonymization-cedar= | Common Cedar POO token profile | Lightweight bridge only |
| =google-sdp= | Google SDP wire contract | Lightweight bridge, no =cedar-policy= |

Only Rust capabilities with an actual implementation receive a feature.
Lean-only controls are published as Cedar artifacts for the deploying Host;
this package does not create placeholder flags for them.

The provider-neutral binding lives in [[file:../mrr-data-security/README.org][Data Protection]].
The public =TokenInputBinding= relates a selected value digest and actual
per-record context to one =mrr-data= snapshot root and a common token
profile. =compatible_inputs= uses the same recipe/context rule as the Lean
AES-SIV table capability; =hmac_catalog_separated= checks declared HMAC
key-domain reuse across scopes. These metadata checks do not authenticate
the profile, key material, input bytes, provider response, or authorization.
The deploying Host must provide those facts and control execution.

[[file:src/authorization.org][Scoped claim matching]] compares the exact
requested de-identify or re-identify effect against Host-authenticated claim
fields and current governance state. It is not a policy decision. With the
optional Google feature, [[file:src/google_sdp_binding.org][Google selection
binding]] checks the selected dataset, field, context, profile, and SHA-256
of the exact UTF-8 value before constructing the bridge's AES-SIV request.
The value digest convention is required for this Google operation; generic
=TokenInputBinding= remains independent of a hash algorithm. The Cloud path
checks the same projected gate relations as the public Cedar POO Cloud
DataProtection model and keeps the release identity with the checked output.
For MRR Arrow children, [[file:src/google_sdp_binding.org][Arrow-backed preparation]]
also checks the catalog, child content, schema, row, and selected cells.

The benchmarks are Cargo bench targets using stable Rust's
=std::hint::black_box= and =std::time::Instant=. The HMAC catalog check uses a
borrowed-key hash index at deployment time. The Google benchmark separates
claim matching, Cloud gate and release checks, SHA-256 selected-value
checking, and request construction. Cloud preparation and the baseline Google
preparation run in alternating order by round to reduce timing drift.
Measurements are batch averages under release optimization; they do not
measure Cedar authorization, network, KMS, or provider execution.
