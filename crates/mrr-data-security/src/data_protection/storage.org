#+TITLE: Storage Effect V1 and Raw Snapshot Admission
#+OPTIONS: toc:nil

[[file:storage.rs][storage.rs]] implements the physical projection of Cedar
POO Spec's =CedarPooSpec.Data.StorageEffectV1= rule. The checked
[[file:../../fixtures/storage-effect-v1.json][17-case fixture]] is generated
by SPEC's =Examples/Data/StorageEffectFixture.lean= and replayed by this
crate's test. It includes two allowed raw effects and negative cases for
restricted custody, tenant/owner mismatch, substituted operation, subject,
purpose, source, destination or CID, changed policy/lineage/epoch, expiry and
denial. The fixture is test evidence, not an authorization credential.

The V1 projection keeps Cedar entity UIDs as separate =type= and =id= fields.
Its snapshot root is a parsed CID; the fixture parser requires canonical
lowercase CIDv1 base32 text. The policy root and lineage revision are exact
strings, not local hashes of policy source. An operation ID is an opaque
Host-issued single-use value. All of these fields participate in the exact
claim comparison. The Host rejects SPEC natural-number epoch and time values
that do not fit Rust's =u64= instead of truncating them. The Host authenticates
labels, source-to-snapshot lineage,
destination configuration, policy root and current state. The Host also
atomically redeems an approval and records the committed effect. Rust's
=check_raw= is a borrowed, allocation-free comparison with a 64-label and
64-owner bound; it does not evaluate Cedar or persist any approval.

The optional =raw-publish= feature checks the V1 projection before invoking
the existing Tokio-backed =TransferSession=. It checks that the projected CID
is the actual snapshot root and that the tier is remote. Restricted raw bytes
are rejected before any transfer operation or remote PUT. The focused test
also publishes an unrestricted three-block fixture. The wrapper checks only
before the transfer; the generic publisher has no pre-root reauthorization
hook, so this is not a durable Host commit protocol. =check_raw= supports a
durable-local projection, but no guarded local-write wrapper exists yet.

Generic =ContentStore= and =publish_snapshot= transports remain label-blind.
The legacy static-edge worker lacks authenticated sensitivity and tenant
facts, so it is not a sensitive-data Host. Restricted storage still needs a
protected envelope, ciphertext outbox, destination-specific authorization
and audited commit as described in
[[file:../../../../docs/architecture/sensitive-data-storage-plane.org][the architecture proposal]].
